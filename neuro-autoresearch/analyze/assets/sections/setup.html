The current setup in one place: what every evaluation writes to the database, and the exact columns the agent reads back as feedback.

The database is an append-only ledger. Each python -m harness.run evaluates the current model once and appends a single row to a per-study CSV (results/<study>.csv, or <study>__<roi>__<run>.csv when a reward region and run tag are set). Rows are never overwritten, so the whole hill-climb history — every model tried, in order — is preserved. The agent reads this same table back as its feedback signal: it sees what it proposed, how each model scored, and how the score breaks down by brain region.

Who fills what. The agent writes three free-text fields per model — model_name, idea (the hypothesis), and summary (what the model computes) — and the model itself determines n_params. Everything else is filled by the fixed harness: the counters, the timing, and above all the reward (test_corr) and its per-region breakdown, which the agent cannot touch. That separation is what keeps the score honest.

The scalar reward narrows to one region (chosen by NEURO_ROI), but the readout still fits all nsdgeneral voxels, so every region's corr_<region> is logged on every row — that is what makes the cross-region heatmap below possible.
