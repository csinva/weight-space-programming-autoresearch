How did the search actually progress? These views read the ledger's iterations, reward values, train–test gap, and status field to characterize the search dynamics rather than any single model.

  • Progress — best reward as a function of iteration, or wall-clock when reliable seconds are present.
  • Failure rate — non-ok status rows as a percentage of all iterations.
  • Generalization gap — train_corr − test_corr tracks how much the ridge readout overfits as features grow richer.
  • Iteration accounting — scored rows versus failed rows when compute timing is not available in the report data.
