neuro·autoresearch / overview an AI that designs models of the brain — without ever training one

The big question

Can an AI discover better models of the brain — without training one?

Neural encoding is the task of predicting recorded brain activity from the stimulus a person saw or heard. Here an agent writes a small computational model in code, a fixed harness scores how well its activations predict real fMRI / MEG, and the agent iterates to push the score up. The unit of progress is a single file, model.py; the unit of truth is a single number, test_corr.

Read out & score

A ridge regression linearly predicts recorded neural activity from those activations. The reward is test_corr — held-out Pearson r. Only the readout is fit.

harness, fixed

The model is frozen; the only thing that gets fit is the linear probe — and that probe is the evaluation. So the score can't be gamed by memorizing the data.

02

Why never train?

The features are the hypothesis

In computational neuroscience, the standard way to test a theory of how the brain represents a stimulus is encoding: extract features, fit a linear readout, measure held-out predictivity. If you let an optimizer train the model on the brain data, a high score just means it memorized the dataset. By forbidding training, a high test_corr becomes honest evidence that the hand-designed representation genuinely resembles the brain's.

The goal: beat a network that was trained

The bar isn't the raw-pixel floor — it's a frozen ImageNet-pretrained AlexNet (fc7, 4096-d) read out with the identical ridge. The challenge: can a model whose weights you simply wrote down out-predict a network trained on a million labelled images?

Early visual cortex — untrained wins

In V1, V2 and V3, hand-built Gabor-energy models with divisive normalization beat AlexNet outright (V1: 0.428 vs 0.342). These regions compute simple, writable operations — oriented contrast, luminance, colour-opponency.

High-level cortex — untrained trails

Every category-selective area falls short: faces (FFA), places (PPA), bodies (EBA), words (VWFA). The widest gap is EBA (0.290 vs 0.436). These encode learned semantics no fixed filter bank captures.

Early vision is hand-writable. High-level meaning must be learned.

One interface, every modality

Three real datasets

Every dataset flows through one unified data interface (NeuralSet / NeuralFetch) — no raw file or network I/O in the loop. The same model and reward run untouched across fMRI & MEG and across image, text and audio stimuli.

nsd

imagefMRI

Natural Scenes Dataset, subject 1. 10k images, each shown ~3×. The active study — where all the real results live.

X = 16×16×3 RGB → 768 dims · Y = HRF-peak response over 15,724 voxels

text

audiofMRI

Le Petit Prince, narrative listening. Each spoken word triggers a segment; X is the Mel spectrum at the word.

stimulus & neural windows decoupled so the HRF delay never leaks into X

meg

audioMEG

LPP-Listen MEG — the loop's electrophysiology modality. Each word triggers a 0.5 s epoch; MEG is near-instant, so windows coincide.

selected at run time with NEURO_DATASET=meg

Adding a dataset is pure configuration — append a Dataset(...) to PRESETS; the harness and models need no changes.

How it's built

Two files you touch.
Everything else is frozen.

The whole architecture follows from one decision: make the evaluation immutable. If the agent could edit the scorer, the reward would be meaningless. So the editable surface is tiny and the harness is fixed by design — that fixedness is what makes a higher test_corr a real, comparable improvement rather than a moved goalpost.

01

The mental model

Editable vs. fixed

✎ Editable — the agent's whole world

model.py  the one evolving model: a callable X → activations, weights written in code. Seeded as the identity.

experiment.py  vestigial stub (LOG_SLICES=[]); the search no longer uses it.

+ one env-var dial, the only harness knob: NEURO_DATASET (which preset). The reward is the dataset's fixed region (NSD: ventral) — no ROI knob.

🔒 Fixed — the trustworthy core

All of harness/: the dataset registry, the NeuralSet data layer, the ridge readout, the scoring, the append-only ledger, and the per-study Study subclasses.

Plus the agent-facing prompt search/proposer.md. None of it is touched between iterations.

Verified: the GCV ridge reproduces sklearn's RidgeCV to ~1e-13, and all three tests pass with no skips.

The record of record

    
The CSV ledger

    
One run appends exactly one row — one run = one model = one iteration. The
      history is append-only, so the iteration column counts every model ever tried. A model that
      raises or returns a bad shape doesn't crash the loop: it's caught and logged as a
      status="error" row with NaN reward.

    

      
columnwhat it records

      
        
iterationmonotonic counter — every model tried across all runs

        
model_name · idea · summarythe hypothesis and what the model does, logged verbatim

        
n_paramshonest count of hard-coded weights (0 for a parameter-free transform)

        
test_corr ★the reward — held-out mean per-voxel Pearson r over the reward region

        
train_corr · gaphigh train + low test = the readout overfit, not progress

        
best_so_farrunning max test_corr in the file

        
statusok, or a one-line error string for caught failures

        
corr_<region>every region's predictivity (V1…VWFA) — frozen on the first row

⚠ The one gotcha

      
The unattended launcher search/search.sh scaffolds runs/<dataset>__<date>/
        then supervises two always-on loops — the N-proposer pool search/propose.sh (10 headless
        Copilot CLIs, each editing its OWN sandbox model.py and queueing it) and the single
        evaluator search/evaluate.sh that scores them one at a time on the GPU — coordinating only
        through the run's SQLite DB search.db (reached via the lab API). Proposers are
        self-paced (each waits only for its OWN model's score), so there is no wave barrier. It
        self-terminates at the --hours
        deadline, and on shutdown (or a Ctrl-C) it resets any orphaned running rows so a
        kill resumes losslessly — no external timeout wrapper needed.
        e.g. search/search.sh nsd FFA 128 --hours 12
