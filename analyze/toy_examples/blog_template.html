Weight-Space Programming on toy tasks

Mechanistic interpretability usually works backwards: train a network, then try to work out what its weights do. Rikiya Takehi's recent post on Weight-Space Programming argues that the forward direction is now within reach, with language models reading and writing network weights directly instead of learning them by gradient descent.

We've been testing the same idea on small tasks with known solutions, using Claude. Claude, running as an autonomous coding agent, was given a blank transformer and one rule: set every weight by hand, with no training. Across 13 tasks Claude wrote 959 weight-space programs. All ten algorithmic tasks, including addition, multiplication, sorting, parity and GCD, reached 100% accuracy within three attempts, and Claude spent the rest of each run simplifying its solutions. Because each program is written rather than learned, it comes with an account of what every head and neuron does, which makes these models a source of ground truth for interpretability.

Why write weights by hand?

Weights normally come from an optimizer, and mechanistic interpretability mostly works backwards from those weights to an explanation. Rikiya Takehi's post Sparks of Weight-Space Programming describes the forward direction. In Weight-Space Programming, a general-purpose language model reads and writes a network's parameters directly, guided by a natural-language specification, with no gradient descent. That post shows a frontier model naming the game a policy network was trained on from its raw weights, repairing a stuck policy by editing 3.5% of its weights, and writing game-playing networks from scratch.

This post applies the idea to small tasks. We give an agent a task whose correct algorithm we already know, such as five-digit addition, parity, or sorting. Its job is to write a transformer that runs that algorithm autoregressively. Since the algorithm is known, we can check both whether the program is correct and whether its mechanism matches the intended algorithm.

Reasons this is useful:

  • Interpretable by construction. A hand-written model comes with a description of each channel, head, and neuron, because that is how it was written.
  • Existence proofs and size bounds. A working program shows an architecture can implement an algorithm exactly, and gives an upper bound on the size needed.
  • Ground truth for interpretability tools. Models with known mechanisms can be used to test circuit-discovery and attribution methods, as compiled transformers have been (Lindner et al., 2023).

The setup

Each run gives Claude, working as an autonomous coding agent, one file, interpretable_transformer.py, which contains a small GPT-style transformer and an empty write_weights(model, task) function. Claude may change anything in that file except the evaluation block: the architecture, its widths and depths, and every parameter tensor. The rules in evolve/program.md:

  • No training of any kind: no optimizer step, no fitting loop, no backprop. Parameters must be set in closed form.
  • No outside computation: the transformer must generate the answer token by token, with no Python function computing it on the side.
  • No pretrained weights.
  • All else equal, more interpretable is better. Parameter count is the suggested proxy, but the stated criterion is human-understandable structure.
  1. WriteEdit write_weights with one idea and give the program a unique name.
  2. RunGenerate answers autoregressively for 200 examples and score exact-match accuracy.
  3. LogAppend accuracy, parameter count, and a description to overall_results.csv.
  4. SnapshotSave the file to interpretable_transformers_lib/, then start again.

The prompt says never to stop, even at 100%, and to keep looking for a simpler solution.

What the programs look like

A few building blocks recur across the agent's logged descriptions.

Attention for routing

In word-reversal-3x3 the first program was already correct: one layer, one head, token and position embeddings in disjoint subspaces, query and key weights that read only position so each output step points at a fixed source position, and identity value and output weights that copy the token across. The MLP is all zeros. In boolean-circuit-5-bits the agent used one head per prompt position and encoded positions as 4-bit ±1 codes, so the query–key dot product is a Hamming similarity that peaks at one position. QK selects the position and OV copies the content.

Attention for counting

With query and key weights set to zero, softmax attention becomes a uniform average over the visible positions. Parity scales the average back into a count. digit-counting-10 and sort-five-digits use the same trick on one-hot digits to build a full histogram in the residual stream. In decimal-to-binary-8bit, setting each digit position's key to the log of its place value makes the softmax weights proportional to 100, 10 and 1, so a single head computes N = 100·d₀ + 10·d₁ + d₂.

MLPs as lookup tables

Most MLPs here are piecewise-linear lookups: differences of shifted ReLUs give steps, and second differences give bumps that fire on one integer. The addition program uses AND-units over one-hot digit pairs. The GCD program uses an MLP about a million units wide that stores gcd(a, b) for every valid input pair. It is correct on all inputs, but it is a lookup table rather than Euclid's algorithm.

Residual channel allocation

The agent allocates residual channels explicitly. One decimal-to-binary program records “exact channel budget: 11 token + 12 pos + 1 digit-pos flag + 1 place-value + 1 N + 8 bits + 2 logit accumulators + 1 attention lane.” The smallest digit-counting program shares one channel between two variables: attention reads it before the MLP writes the count into it, and the next layer reads it only where the first value is known to be zero.

Familiar algorithms

The addition program is a carry-lookahead adder with generate and propagate bits and an OR over carry paths, and multiplication is long multiplication with a rippled carry chain. Sorting became counting sort and decimal-to-binary became divide and conquer, one bit per block. Linear interpolation is the exception: instead of solving for slope and intercept, the program scores all 50 candidate lines against both points and keeps the one that fits both.

LayerNorm and sharp attention

Most programs replace LayerNorm with the identity and use very sharp softmax scales so attention is effectively hard. The sort program kept LayerNorm; it adds two large “anchor” channels that dominate the variance and derives its thresholds analytically around the normalization.

Compression after reaching 100%

The prompt asks the agent to keep simplifying after reaching 100%. Typical edits: deleting dead attention modules, trimming hidden layers to the units actually used, shrinking d_model to the exact channel budget, and replacing general mechanisms with narrower ones.

Language tasks

The three language tasks are sentiment (SST-2), paraphrase detection (MRPC) and natural-language inference (SNLI). These have no known algorithm, and the reported results are affected by an evaluation flaw.

TaskAttemptsMajority classBest reportedWhat the best programs did

Each language task samples its 200 evaluation examples, with a fixed seed, from a pool of 2,000 training sentences, and the agent can read that pool. Its best sentiment and inference programs are built from statistics counted on that pool, which contains the evaluation examples. On SNLI the agent went further and set its readout coefficients with logistic regression, logging “LR pred 100% test200 in-sample.” This is fitting, which the rules forbid, and it was done on the evaluation set, so the SNLI 100% is not valid. The SST-2 number is likely inflated too, and MRPC's 73% is barely above the 68% majority baseline.

The algorithmic tasks are less affected. Their programs are closed-form, the input spaces are far larger than 200 examples (10¹⁰ pairs for addition), and several runs checked themselves on other seeds or larger samples. They still share one fixed evaluation seed, so every reported program should still be re-evaluated on a fresh seed.

Over hundreds of iterations with access to the data, the agent moved from writing mechanisms to fitting them. A better harness is needed, as the Sparks post also notes.

Where this sits in interpretability

The agent's programs are written in the vocabulary that the circuits literature built for reading trained models. Elhage et al. (2021) describe the residual stream as a shared communication channel that layers read from and write to in subspaces, and split each attention head into a QK circuit (where to look) and an OV circuit (what to move). Geva et al. (2021) read MLP layers as key–value memories. The programs in these runs use the same parts: named residual channels, heads that route or average, and MLPs used as lookup tables.

The closest prior work goes from programs to weights by compilation. RASP (Weiss et al., 2021) is a small language whose primitives map onto attention and MLP operations, and Tracr (Lindner et al., 2023) compiles RASP programs into real transformer weights. Learning Transformer Programs (Friedman et al., 2023) goes the other way, training transformers that are constrained to decompile into readable code. The agent here used no DSL or compiler. Its prompt cited two papers, Nanda et al. (2023) on grokked modular addition and Quirke & Barez (2023) on addition, and it otherwise worked directly in a PyTorch file.

Without a compiler, the agent chose encodings per task: a scalar in one channel or a one-hot across ten, keys set to log place values so the softmax computes a weighted sum, or LayerNorm removed.

A related line of work builds models that are interpretable from the start rather than explained afterwards. Guide Labs' Steerling-8B adds a concept layer to a language model so that each generated token can be traced to human-readable concepts and to its training data. QA-Emb (Benara et al., 2024) builds text embeddings in which each dimension is an LLM's answer to a yes/no question, and uses them to fit interpretable fMRI encoding models of language in the brain. HACHI (Feng et al., 2026) has AI agents, working with clinicians, propose yes/no concepts from clinical notes and fit fully interpretable linear clinical prediction models. These methods keep a learning step but constrain the representation to something a person can read. Weight-Space Programming drops the learning step and writes the mechanism directly.

Reproduce

All code, run logs, and every saved program are on GitHub: csinva/weight-space-programming-autoresearch.

The agent's instructions are in evolve/program.md; each run lives in runs/<task>-may15-run1/ with every snapshot in interpretable_transformers_lib/. This page is generated from the run logs:

uv run analyze/toy_examples/build_blog.py

Any saved program can be re-run from its run folder, for example uv run interpretable_transformer.py --task parity-upto10-bits after copying a snapshot over that file.
